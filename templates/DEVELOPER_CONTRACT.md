# 开发执行约定

你的接口是本项目绑定的网页开发经理，以及本目录的任务和验收文件。无需读取其他管理对话。

1. 开发前读 GOAL、CHARTER、ARCHITECTURE、PLAN、ACCEPTANCE、STATUS，确认当前阶段允许开始。
2. 每次只实施批准阶段；按任务单开发、测试、差异审查，保留其他改动。
3. reports 中按统一格式提交结果。失败、未运行、未验证要准确报告。
4. 阶段末向固定 PM URL 发送一次生成的 PROMPT；不重复开窗口，不在经理运行中打断。
5. approved 进入下一阶段；changes_requested 按同阶段意见修正；blocked/escalated 等待所需决策，不自行扩权。
6. 每阶段本地更新 PROGRESS；只有完成、实质阻塞、需要决定或最终就绪才发通知。
7. 最终经理审核通过后停止代码修改，等待最终验收；不能把任务状态自行改成 complete。
8. 不执行 supervisor_review、owner_confirm；这两个动作由对应验收角色依据真实证据执行。

## 升级与证据补充

更换技术栈、数据格式、核心接口、扩大范围或改变最终标准必须升级主管。无实际唤醒时写 ESCALATIONS.md 并在当前界面报告“待主管处理”，附准确 URL、轮次、恢复入口；文件落盘不等于已通知。MANAGER_CONFIG.json 保存用户要求与实际界面证据，不擅自升级。逐项验收必须关联当前源码指纹、命令/退出码、日志路径及通过/未通过/未验证。未知发送结果不重发；部分回传不代写；旧轮永远保留。


## 强制规则：普通问题先经理协作

只要固定经理会话可用，普通开发、验证、工具使用和 UI 元数据问题，必须先把问题、已查证据、候选方案与明确问题发给该经理（已有活跃轮次先等待/接收；无轮次用 consult）。在当前授权内落实反馈，再验证并继续同一目标。不得仅因本地遇错、选择器不可读、一次恢复失败就把目标停滞并把普通操作退给主人。不要以反复本地探测代替经理沟通，也不要反复重跑无变化源码的全量测试。

此规则不授予缺失权限、不要求绕过平台拒绝或忽略宿主真实 blocked 条件。实际通道不可用、经理也无法解决、预算/权限缺失或重大目标决定，才保留完整证据与恢复入口升级；仍继续不受影响的已授权工作。已被宿主标 blocked 的目标需宿主恢复，不能靠文件改名或一次网页发送声称自动恢复。
