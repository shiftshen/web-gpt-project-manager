# 汇报、文件责任与交流频率

| 文件 | 写入者 | 读取者 |
|---|---|---|
| GOAL / CHARTER / ARCHITECTURE / MILESTONES | 主管，根据用户授权 | 经理、开发者 |
| reports/<阶段>-<尝试>.md 与 evidence/ | 开发者 | 经理、主管 |
| rounds/<轮次>/HANDOFF / SNAPSHOT / REQUEST | 本地交接脚本 | 经理 |
| rounds/<轮次>/outbox/* | 网页经理经 WebCodex | 开发者、主管 |
| PLAN / ACCEPTANCE / STATUS / DECISIONS | accept 后脚本同步；决策注明来源 | 全部协作者 |
| PROGRESS | 开发者阶段末更新 | 经理、主管 |
| ESCALATIONS | 本地协调者汇总经理的升级建议 | 主管 |
| FINAL_REPORT | 开发者整理，经理审查 | 主管、主人 |
| supervisor/ | 主管 | 主人；开发者只需结论 |
| owner/ | 主管记录主人明确回复与来源 | 主管 |

每阶段报告包含：阶段目标、验收条件完成数、实际改动、测试命令/退出码/日志、版本或指纹、未完成项、风险、所需决策、下一步建议。禁止没有分母的百分比、把未运行说成通过、拿旧测试证明新源码。

默认开发者↔经理每阶段一轮对话；返工完成再一轮。平常调试不发消息。阶段通过、实质阻塞/需要决定、最终就绪才向用户当前界面报告。主管按用户调用或实际支持的宿主唤醒读取文件，不宣称自动收到跨会话通知。

没有自动发邮件/Slack，没有隐形计时器。共享文件是持久记录，网页消息携带短摘要、轮次及路径。没有浏览器控制能力的模型应说明限制，不能假报已发送；已授权且具备能力则实际发送，不要求用户充当文件搬运者。

验收采用 templates/STAGE_REPORT.md 的逐项证据映射；最终报告覆盖所有必需项，而非仅成功项。迁移前未执行过的历史验证标记“开发者报告，未独立复核”。升级记录和通知状态规则见 authority.md。
